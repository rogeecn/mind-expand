# 产品路线图（6 个月）

## 目标与定位
- **目标**：从“AI 思维导图工具”升级为“决策与研究的认知操作系统”，提升高价值场景的复用率与留存。
- **定位**：复杂问题的结构化拆解 + 深度对话推演 + 行动结论输出。

## 当前问题诊断（痛点）
1. **高价值闭环不足**：AI 能拆解，但缺少“结论归纳与行动计划”的闭环。
2. **场景泛化过宽**：无明确垂类聚焦，导致用户难以形成持续复用习惯。
3. **协作与复用不足**：本地数据隐私好，但不利于团队协作与知识资产沉淀。
4. **进入门槛高**：首次使用缺乏“强引导模板”，用户不确定如何开始。

## 路线图原则
- **先打穿高价值场景，再扩展通用性**。
- **先建立复用与留存的行为闭环，再扩展新功能**。
- **先本地体验稳定，再逐步解锁云同步能力**。

---

## Phase 1（第 1-2 个月）：场景收敛 + 可执行闭环

### 核心目标
让用户在 1 次完整使用中得到“可执行结论”。

### 关键动作
1. **场景模板化（高价值场景）**
2. **结论输出模块（Actionable Summary）**
3. **结构化回放（Insight Trace）**

### 实施规划（功能级）

#### 1) 场景模板化（高价值场景）
- **问题**：新用户不知道从哪里开始，导致首轮体验流失。
- **实现建议**：
  - **数据模型**：新增 `templateId?: string` 到 `TopicRecord`（Dexie v11）。模板定义存放于 `src/lib/templates.ts`（静态 JSON），包含 `id/title/rootTitle/questions/seedNodes`。
  - **UI 入口**：`TopicForm` 增加模板选择步骤，展示 4 类模板（投资研究 / 产品策略 / 市场分析 / 竞品拆解）。
  - **初始化逻辑**：创建主题时，自动生成模板的种子节点（seedNodes）+ 预置引导问题写入 `suggestedFocus`。
  - **AI 约束**：模板内容注入 `globalConstraints`，提升 AI 展开的一致性。
- **交付物**：`TemplatePicker` 组件、模板 JSON、TopicForm 改造、Dexie schema 升级。
- **验收标准**：新用户首次创建完成率提升 > 20%。

#### 2) 结论输出模块（Actionable Summary）
- **问题**：用户有结构，但缺少明确“下一步行动”，难以形成闭环。
- **实现建议**：
  - **数据模型**：新增 `summaries` 表（Dexie v11），字段：`topicId`, `coreFindings[]`, `risks[]`, `nextActions[]`, `sourceNodeIds[]`, `createdAt`。
  - **AI Action**：新增 `generate-summary` Server Action + `summary.prompt`，输入：root + constraints + nodes + chat insights；输出结构化 JSON。
  - **UI**：新增 `SummaryPanel`（MapToolbar 或 NodeDetailsPanel Tab），支持“生成/刷新/导出”。
  - **导出**：Export JSON 增加 `summaries`；同时支持 Markdown/PDF 导出。
- **交付物**：Summary 数据表 + Action + UI + Export 适配。
- **验收标准**：每个主题至少生成 1 个结论卡片（平均 >= 1）。

#### 3) 结构化回放（Insight Trace）
- **问题**：结论不可追溯，用户难以验证或复用。
- **实现建议**：
  - **来源绑定**：Summary 输出包含 `sourceNodeIds`。因 AI 不知 ID，可先用“标题匹配 + 手动确认”策略；后续引入向量匹配。
  - **交互**：点击结论卡片高亮节点 + 自动定位路径；支持“跳转到结论来源”。
  - **可解释性**：在结论卡片底部展示“引用节点列表”。
- **交付物**：高亮路径逻辑、结论-节点映射、交互入口。
- **验收标准**：至少 70% 结论卡片能追溯到具体节点。

### 验证指标
- D7 留存 > 20%
- 平均每个主题输出 1+ “行动结论卡片”

## Phase 2（第 3-4 个月）：复用增强 + 个人知识资产

### 核心目标
让用户形成“跨主题复用习惯”，构建长期资产。

### 关键动作
1. **跨主题引用（Cross-Map Reference）**
2. **个人知识库（Local Knowledge Base）**
3. **导航系统升级**

### 实施规划（功能级）

#### 1) 跨主题引用（Cross-Map Reference）
- **问题**：洞察无法跨主题复用，价值积累断裂。
- **实现建议**：
  - **数据模型**：新增 `referenceNodes` 表或在 `NodeRecord` 中新增 `refNodeId?: string`。引用节点只读，展示来源主题标题。
  - **UI**：`NodeDetailsPanel` 增加“标记为可复用”按钮；`TopicSidebar` 增加“引用库”。
  - **交互**：插入引用节点时显示“链路标识”，点击可跳转原主题。
- **验收标准**：跨主题引用率 > 20%。

#### 2) 个人知识库（Local Knowledge Base）
- **问题**：节点难检索、难归类，降低复用。
- **实现建议**：
  - **数据模型**：在 `NodeRecord` 增加 `tags?: string[]`；新增 `nodeTags` 索引辅助检索。
  - **UI**：NodeDetailsPanel 增加标签管理；新增全局搜索面板（标题/描述/标签）。
  - **交互**：搜索结果可直接定位节点并高亮。
- **验收标准**：用户主题数 > 5，标签使用率 > 30%。

#### 3) 导航系统升级
- **问题**：用户找不到“高频主题”，复用效率低。
- **实现建议**：
  - **数据模型**：`TopicRecord` 新增 `lastOpenedAt`, `openCount`, `isStarred`。
  - **UI**：Sidebar 增加“最近使用 / 高频主题 / 收藏”分区。
- **验收标准**：复访主题占比提升 > 25%。

### 验证指标
- 用户平均主题数 > 5
- 跨主题引用率 > 20%

## Phase 3（第 5-6 个月）：协作与商业化准备

### 核心目标
为 ToB 或团队协作打基础，并建立付费驱动。 

### 关键动作
1. **双模式数据体系（Local-first + Optional Cloud）**
2. **共享与协作（Team Sync）**
3. **高级模型与私有化能力**

### 实施规划（功能级）

#### 1) 双模式数据体系（Local-first + Optional Cloud）
- **问题**：本地体验安全，但无法长期协作与跨设备。
- **实现建议**：
  - **架构**：新增 `SyncAdapter` 抽象层（Local/Cloud）。
  - **策略**：默认 Local；Pro 用户可启用 Cloud，支持双向同步。
  - **冲突解决**：默认 Last-write-wins + 手动冲突提示。
- **验收标准**：启用同步的用户 > 10%，同步失败率 < 1%。

#### 2) 共享与协作（Team Sync）
- **问题**：团队协作无法落地，阻碍 ToB 收入。
- **实现建议**：
  - **权限模型**：只读 / 可编辑 / 管理员。
  - **共享方式**：邀请链接 + workspace 绑定。
  - **版本控制**：保留变更记录与回滚点。
- **验收标准**：团队账户占比 > 15%。

#### 3) 高级模型与私有化能力
- **问题**：高端用户需要自定义模型、企业合规。
- **实现建议**：
  - **对齐现有任务**：复用 `Settings` 机制（模型选择 / API Token / BaseURL）。
  - **企业能力**：允许私有模型接入、私有部署。 
- **验收标准**：付费转化率 > 3%。

### 验证指标
- 付费转化率 > 3%
- 团队账户占比 > 15%

---

## 风险与对策
- **风险：功能扩展过快，导致体验碎片化**
  - 对策：严格限定场景模板 + 强化复用和闭环指标。
- **风险：本地存储限制长期协作**
  - 对策：先做“可选云同步”，降低迁移阻力。
- **风险：用户学习成本高**
  - 对策：模板化 + 一键示例，降低首次使用难度。
